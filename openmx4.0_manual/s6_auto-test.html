6 Automatic Test Execution

This section is for users who want to verify, beyond a single example, that the main OpenMX functionalities have been installed correctly. Run the automatic tests only after the basic test calculation in Section 5 has succeeded. At first, it is sufficient to check whether each test completes normally; the detailed timings and reference values can be examined later.

In addition to the calculations explained in Section 5, if you would like to confirm that the main functions of OpenMX have been installed correctly, we recommend performing the automatic test execution. To run this automatic test, execute OpenMX using the following command.

In the case of MPI parallelization: 

     % mpirun -np 8 openmx -runtest

In the case of MPI/OpenMP parallelization: 

     % mpirun -np 8 openmx -runtest -nt 2

When running a parallel calculation, you may also specify other options for mpirun. In this test, OpenMX calculates 14 input test files and compares the results with the reference data stored in work/input_example. The comparison results (absolute differences in the total energy and forces) are stored in the file runtest.result in the work directory. The reference data were calculated on a computer with a single 3.6 GHz Xeon processor. If the absolute differences are within the seventh decimal place, the installation can be regarded as correct. This comparison was carried out on the same Xeon cluster used for the reference calculations, using 14 MPI processes × 2 OpenMP threads. Because floating-point operations depend not only on the computer environment but also on the number of processors used in the parallel calculation, the above example shows that differences can appear even when the same computer is used. Since the elapsed time for each job is also output, it is also possible to compare differences in computational speed among environments. The work/input_example directory contains runtest.result files generated on several platforms.

If you would like to create the reference data files by yourself, please execute OpenMX using the following command.

     % ./openmx -maketest

By this command, OpenMX generates the corresponding *.out files in the same directory for the *.dat input files in the work/input_example directory. By adding new input files (dat files), the corresponding *.out files can be used in the next automatic test execution, but note that this procedure overwrites the existing output files in work/input_example. If developers or heavy users would like to confirm the reliability of the code, please also refer to Sections 72 and 73.
