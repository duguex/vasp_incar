7 Automatic Test Execution for Large-Scale Systems

This section is for users who want to benchmark larger systems and confirm how OpenMX behaves on many cores. Read this section after the standard automatic tests, because the purpose here is performance checking rather than a first installation check. When interpreting the timings, pay attention to the numbers of MPI processes and OpenMP threads, as well as to machine-dependent settings.

If you would like to check the performance of your computer through benchmark calculations for larger-scale systems, execute the test calculations automatically using the following commands.

In the case of MPI parallelization: 

     % mpirun -np 112 openmx -runtestL

In the case of MPI/OpenMP parallelization: 

     % mpirun -np 112 openmx -runtestL -nt 2

By executing these commands, OpenMX calculates 16 test input files and compares the results with the reference data stored in work/large_example. The comparison results (absolute differences in the total energy and forces) are stored in the file runtestL.result in the work directory. The reference data were calculated on a 3.6 GHz Xeon cluster machine using 28 MPI processes. If the absolute differences are within the seventh decimal place, the installation can be regarded as correct. Since this automatic test execution requires a large amount of memory, a memory violation (segmentation fault) may occur when the number of used cores is small. In addition, the above example shows that even when a total of 256 cores are used, about 20 minutes are required.
