71 Interfacing external programs via the OpenMX API

OpenMX is usually used as a standalone executable with an input file. However, when one wishes to call OpenMX from another program, or to run multiple input files simultaneously within a single MPI job, it is convenient to interface external programs through the API (Application Programming Interface). With the OpenMX API, the external program initializes MPI, splits MPI_COMM_WORLD into multiple subcommunicators if needed, and then calls OpenMX from each communicator. For example, this makes it possible to run different input files such as Methane.dat and Cdia.dat simultaneously within a single MPI job.

The use of the API can be understood in two stages. First, under the source directory, one builds the API itself and the external executable codes that use the API. Second, the generated executable files or Python module are copied into the work directory and executed there using the input files placed in that directory. For first-time use, it is helpful to understand these two stages separately.
