28.1 MPI Parallelization

MPI parallel calculations can be executed on distributed-memory parallel computers in order to handle large-scale systems.

28.1.1 O(N) Calculations

Since O(N) methods have an algorithmic structure well suited for parallelization, high parallel efficiency can be expected. A typical MPI execution is performed as follows.

     % mpirun -np 4 openmx DIA512_DC.dat > dia512_dc.std &

work/DIA512_DC.dat is the input file used to perform an SCF calculation for diamond consisting of 512 carbon atoms by means of the divide-and-conquer (DC) method. The speedup ratio as a function of the number of MPI processes is shown in Fig. 30(a). This parallel calculation was carried out on a CRAY-XC30 (Xeon processors, 2.6 GHz), and the speedup ratio was evaluated from the elapsed time for one MD step. When 128 MPI processes are used, the speedup ratio is about 84, and it can also be seen that the parallel efficiency decreases as the number of processes increases. The reason for the decrease in parallel efficiency is that, in the computationally demanding O(N) diagonalization, the number of atoms assigned to each process decreases, and the elapsed time of non-parallelized parts such as disk I/O becomes more pronounced. In addition, for systems in which atomic species or geometrical structures are not uniform, the load balance may deteriorate significantly, resulting in a substantial reduction in parallel efficiency. In MD calculations, an algorithm that dynamically maintains load balance has been implemented so as to improve the parallel efficiency as much as possible. For further information on parallelization, please refer to the sections on the DC-LNO method and the O(N) Krylov subspace method.

28.1.2 Cluster Calculations

In cluster calculations, MPI parallelization is implemented for the loop structure over spin multiplicity and eigenstates. The spin multiplicity is 1 for non-spin-polarized and noncollinear calculations, and 2 for spin-polarized calculations. Parallelization is first applied preferentially to the spin multiplicity, and when a large number of MPI processes is used, parallelization is further applied to the eigenstates. In OpenMX Ver. 4.0, the eigenvalue problem in cluster calculations is solved by the highly parallel eigenvalue solver ELPA [42]. ELPA1 or ELPA2 can be selected by the following keyword.

     scf.eigen.lib      elpa1    # elpa1|elpa2, default=elpa1

The default choice is ELPA1. Although the results are not shown here, our benchmark calculations suggest that the two choices exhibit almost the same performance in terms of computational speed. Figure 30(b) shows the elapsed time and speedup ratio for a spin-polarized calculation of the Mn12 single-molecule magnet. The input file used, Mn12.dat, is stored in the work directory. It can be seen that the speedup ratio is 11 and 17 for 32 and 64 processes, respectively.

28.1.3 Band Calculations

In band calculations, MPI parallelization is implemented for the three loop structures over spin multiplicity, k points, and eigenstates. The spin multiplicity is 1 for non-spin-polarized and noncollinear calculations, and 2 for spin-polarized calculations. Parallelization is first applied preferentially to the spin multiplicity, and when a large number of MPI processes is used, parallelization is further applied in the order of k points and then eigenstates. In addition, when the number of MPI processes is less than or equal to (spin multiplicity)× (number of k points), diagonalization is performed twice for each k point in order to compute the chemical potential and the density matrix. This is done to reduce the memory usage required to store the wave functions. In the first diagonalization, the chemical potential is searched for, and in the second diagonalization, the density matrix is directly computed without storing the wave functions. On the other hand, when the number of MPI processes exceeds (spin multiplicity)× (number of k points), each process no longer needs to store wave functions for many k points in memory. Therefore, only one diagonalization is required, and the computational efficiency appears to improve. As shown in Fig. 30(c), the speedup ratio as a function of the number of processes indicates that the parallel efficiency of band calculations is good. This calculation is a non-spin-polarized band calculation for diamond (64 carbon atoms) with 3×3×3 k points taken into account, and the input file used is DIA64_Band.dat in the work directory. In this case, the spin multiplicity is 1. When scf.Kgrid=(N1,N2,N3) is specified, the number of independent k points in noncollinear calculations is given by Nk=N1⁢N2⁢N3. On the other hand, in collinear calculations, the number of independent k points, Nk, follows the rules below.

  • •

    In the case of scf.Generation.Kpoint=GCenter

    Nk=N1⁢N2⁢N3+2m2
  • •

    In the case of scf.Generation.Kpoint=Regular and all of N1, N2, and N3 are odd

    Nk=N1⁢N2⁢N3−12+1
  • •

    In the case of scf.Generation.Kpoint=Regular and at least one of N1, N2, and N3 is even

    Nk=N1⁢N2⁢N32

Here, m is the number of even integers among (N1,N2,N3).
The calculation shown in Fig. 30(c) corresponds to the case of scf.Generation.Kpoint=Regular with all of N1, N2, and N3 being odd. Therefore, the actual number of k points used in the calculation is (3×3×3−1)/2+1=14. Although the speedup ratio exceeds the ideal value when the number of processes is 14 or more, this is due to the algorithmic change explained above. As in cluster calculations, the highly parallel eigenvalue solver ELPA [42] is also used to solve the eigenvalue problem in band calculations. ELPA1 or ELPA2 can be selected by the following keyword.

     scf.eigen.lib      elpa2    # elpa1|elpa2, default=elpa2

Since OpenMX Ver. 4.0, the default choice has been ELPA2. Although the results are not shown here, our benchmark calculations suggest that, in terms of computational speed, ELPA2 is slightly superior.

28.1.4 Full Three-Dimensional Parallelization

In OpenMX Ver. 3.6 and earlier, MPI parallelization was implemented based on data distribution by a one-dimensional domain decomposition method along the a axis of the unit cell. In contrast, OpenMX Ver. 4.0 supports full three-dimensional domain decomposition for data distribution. Therefore, in order to achieve balanced load distribution, there is no need to consider how the unit cell should be specified for parallel calculations. In OpenMX Ver. 4.0, nearly the same parallel efficiency can be obtained regardless of the choice of unit cell vectors.

28.1.5 Available Number of MPI Processes

In OpenMX Ver. 3.6 and earlier, the maximum number of MPI processes available for parallel calculations was limited by the number of atoms in the system. In OpenMX Ver. 4.0, there is no such limitation. Even when the number of MPI processes exceeds the number of atoms, MPI parallelization is carried out as efficiently as possible. This feature is particularly useful when the number of k points is larger than the number of atoms in the system.
