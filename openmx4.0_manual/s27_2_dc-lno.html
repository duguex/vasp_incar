27.2 Divide-conquer method with localized natural orbitals (DC-LNO)

DC-LNO [54] is an improved version of the DC method. The computational efficiency is improved by introducing localized natural orbitals (LNOs), which span the occupied-state subspace. Since the dimension of the LNO basis is reduced compared with that of the original PAO basis, the computational cost is reduced as a consequence. The LNOs are generated by a low-rank approximation to the projection operator onto the occupied states using a local eigendecomposition. Since the generation of the LNOs is non-iterative, it can be carried out very efficiently. As shown in Fig. 24(a), LNOs are assigned to atoms in the long-range region of a truncated cluster, while PAOs are assigned in the short-range region. In this way, the computational efficiency can be improved while maintaining computational accuracy. The method is applicable not only to gapped systems but also to metallic systems, provided that the truncated clusters are sufficiently large (typically clusters containing more than 200 atoms).

As a first step in O(N) calculations using the DC-LNO method, one can perform an O(N) calculation for Si crystal using the input file stored in the directory work as follows.

     % mpirun -np 112 ./openmx Si8-LNO.dat | tee si8-lno.std

This calculation was carried out in 66 seconds using 112 cores on a Xeon cluster machine (2.6 GHz). The input file used is also stored as Si8-LNO.dat in the directory work. As shown in Fig. 24(b), three levels of parallelization have been implemented: atom level, spin level, and diagonalization level. Therefore, for example, for a 1000-atom system, scaling up to 40000 CPU cores is expected in parallel calculations. This is because the product of 1000 atoms × 2 (spin-polarized calculation) × 20 CPU cores (per node) is 40000. Benchmark calculations for the multi-level parallelization will be shown later. To perform hybrid parallelization, please set the following keyword. 

     scf.dclno.threading       on    # off|on

In the hybrid parallelization, the diagonalization at the lowest level is parallelized by OpenMP. The computational accuracy and efficiency of this method are controlled by the following keywords. 

     orderN.HoppingRanges     7.0    # 7.0 (Ang.)
     orderN.LNO.Buffer        0.2    # default = 0.2
     orderN.LNO.Occ.Cutoff    0.1    # default = 0.1

The role of the keyword orderN.HoppingRanges is identical to that in the DC method. The truncated cluster for each atom is constructed from atoms inside a sphere whose radius is specified by orderN.HoppingRanges. Although the proper choice of this parameter depends on the system, a series of benchmark calculations shows that, if orderN.HoppingRanges is set so that the truncated cluster contains about 300 atoms, sufficient accuracy is ensured even for metallic systems.

This setting emphasizes accuracy, and the choice should be examined for each system from the viewpoint of efficiency. A balanced choice in terms of accuracy and efficiency is considered to be around 200 to 300 atoms. The region of atoms to which LNOs are assigned is controlled by the keyword orderN.LNO.Buffer. orderN.LNO.Buffer=0.0 means that LNOs are assigned to all SNAN atoms. On the other hand, when orderN.LNO.Buffer=1.0, PAOs are assigned to all SNAN atoms. This treatment is equivalent to that of the DC method. For SNAN, refer to the subsection 27.4, “User definition of FNAN+SNAN”. The default value of orderN.LNO.Buffer is 0.2, and orderN.LNO.Buffer in the range 0.1∼0.2 is an appropriate choice in terms of both accuracy and efficiency. The LNOs for each atom i are determined by examining the eigenvalues of Λ𝟎⁢i defined by the following equation [54].

Λ𝟎⁢i=∑𝐑⁢jρ𝟎⁢i,𝐑⁢j⁢S𝐑⁢j,𝟎⁢i, (41)

Here, ρ𝟎⁢i,𝐑⁢j and S𝐑⁢j,𝟎⁢i are block elements of the density matrix and the overlap matrix, respectively. Since the eigenvalues can be interpreted as the occupations of the LNOs, by selecting LNOs whose occupations are greater than or equal to the value specified by the keyword orderN.LNO.Occ.Cutoff, one obtains LNOs that span the occupied-state subspace well.

Instead of using the keyword orderN.LNO.Occ.Cutoff, one can directly specify the number of LNOs for each element by the keyword LNOs.Num. For example, when the atomic species are defined as follows,

   <Definition.of.Atomic.Species
     Si    Si7.0-s2p2d1   Si_PBE19
     H     H6.0-s2p1      H_PBE19
   Definition.of.Atomic.Species>

the number of LNOs can be specified as follows.

     <LNOs.Num
       Si    4
       H     1
     LNOs.Num>

In this case, the numbers of LNOs are fixed to 4 for Si and 1 for H. To avoid changes in the number of LNOs during geometry optimization or molecular dynamics simulations, the use of LNOs.Num is recommended rather than orderN.LNO.Occ.Cutoff. Figure 25 compares the DC and DC-LNO methods. In the DC-LNO method, LNOs are used instead of PAOs in the long-range region of the cluster, but the accuracy is found to be comparable to that of the DC method for both gapped and metallic systems. As an example of the application of the DC-LNO method, Fig. 26 shows radial distribution functions (RDFs) of liquid silicon, aluminum, lithium, and SiO2 obtained from high-temperature molecular dynamics simulations. In all cases, the DC-LNO method reproduces well the results of the conventional O(N3) diagonalization method. The obtained RDFs are also consistent with other computational results [55, 56, 57, 58].

The speed-up ratio in MPI parallel calculations of the DC-LNO method is shown in Fig. 27. This is the result for a non-spin-polarized calculation of diamond (a supercell containing 64 atoms). Since the multiplicity of the spin index is 1, nearly ideal behavior is observed up to 64 MPI processes, which is the maximum degree of parallelization at the atom level. Beyond 64 MPI processes, parallelization of the diagonalization is taken into account in addition to atom-level parallelization. When 128 and 256 MPI processes are used, speed-up ratios exceeding the ideal values are observed. This is presumed to be due to more efficient use of cache as a result of reduced memory usage. Good scaling is achieved up to the largest case used in this benchmark calculation, namely 1280 MPI processes. The parallel efficiency, evaluated using the elapsed time for 1 MPI process as the reference, is about 70%. Since each compute node of the PC cluster used in this benchmark consists of 20 CPU cores, it is reasonable that good scaling is observed up to 1280 (=64×20) MPI processes. Thus, multi-level parallelization is shown to be an effective means of reducing computational time on modern massively parallel computers.
