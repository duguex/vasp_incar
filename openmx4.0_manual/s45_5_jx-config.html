45.5 Preparation of the jx Configuration File

Prepare a configuration file in order to run jx. Various control parameters are specified in this configuration file. The configuration file has the same format as the OpenMX input file.

In the following two subsections, for the sake of simplicity, the scfout filename is written as sample.scfout, and the configuration filename is written as jx.config. These are dummy names used only for explanation, and are not actual filenames prepared as they are in the directory work. The actual distributed input examples and actual filenames are shown explicitly in the later Examples subsection as Fe_Cluster_jx.scfout, Fe_Bulk_jx.scfout, and so on.

As an example, jx.config is shown below.

     Flag.PeriodicSum           off       # default - off
     Num.Poles                  60
     Num.Kgrid                  27 27 27
     Num.ij.pairs               236
     Bunch.ij.pairs             236
     <ijpairs.cellid
       1 1 -2 -2 -2
       1 1 -2 -2 -1
       1 1 -2 -2 0
        ...
        ...
       2 2 0 -1 2
       2 2 0 0 -2
       2 2 0 0 -1
     ijpairs.cellid>

Each keyword is explained below.

     Flag.PeriodicSum           off       # default - off

This flag determines how the exchange coupling is calculated. For a periodic system, if this flag is on, the program jx calculates Ji⁢j based on Eq. (47). On the other hand, if it is off, it calculates Ji⁢𝟎,j⁢𝐑 based on Eq. (44). This flag has no role in cluster calculations. In cluster calculations, Ji⁢j is calculated from Eq. (42).

     Num.Poles                  60

This keyword specifies the number of poles NP in the finite-pole approximation of the Fermi function [82] appearing in Eq. (44). As the number of poles increases, the calculation accuracy improves, but the computational time increases in proportion to the number of poles. The appropriate number of poles depends on the system, but for bcc Fe, about 60 poles are required to achieve an accuracy of 0.05 meV. At an electronic temperature of 300 K, 60 poles provide sufficient accuracy for many systems, but we recommend that you check the convergence for your own system at least once.

     Num.Kgrid                  27 27 27

This keyword specifies the number of 𝐤 points for discretization of the first Brillouin zone. The number of 𝐤 points specified here should be the same as or greater than that used in the SCF calculation. In cluster calculations, only the Gamma point is considered automatically, so this keyword has no role.

     Num.ij.pairs               236        # NOTE: Number of ij pairs.

This keyword specifies the number of exchange coupling constants J to be calculated. This value must be equal to the number of lines between the keywords <ijpairs.cellid and ijpairs.cellid>.

     <ijpairs.cellid
       1 1 -2 -2 -2
       1 1 -2 -2 -1
       1 1 -2 -2 0
        ...
        ...
       2 2 0 -1 2
       2 2 0 0 -2
       2 2 0 0 -1
     ijpairs.cellid>

In this field, specify the sites i and j of the exchange coupling constant J to be calculated, and the cell vector 𝐑=l1⁢𝐚1+l2⁢𝐚2+l3⁢𝐚3 of Ji⁢𝟎,j⁢𝐑. Here, 𝐚1, 𝐚2, and 𝐚3 are the unit-cell vectors in the OpenMX input. The order of the data in this field is i j l1 l2 l3. For cluster calculations or calculations taking the sum over periodic images, a different field is specified as follows.

     <ijpairs.nocellid
       1 1
       1 2
     ijpairs.nocellid>

In these Ji⁢j calculations, the cell vector does not appear, and therefore does not need to be specified explicitly.

     Bunch.ij.pairs             236        # default=Num.ij.pairs

With the default setting, the memory consumption may become too large, and the calculation may fail. The above keyword is available to reduce memory consumption. This value should be equal to or smaller than Num.ij.pairs. Using a smaller Bunch.ij.pairs reduces memory consumption, but tends to increase the computational time.
