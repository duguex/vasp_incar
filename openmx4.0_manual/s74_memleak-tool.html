74 Memory leak analysis tool for developers

For developers who modify OpenMX or implement new features, a memory leak analysis tool (leakdetect.cpp and leakdetect.h) is provided. Please follow the procedure below to use this functionality. First, add -DLEAK_DETECT to the specification of CC in the makefile. For example,

   CC = mpicc -O3 -xHOST -ip -no-prec-div -qopenmp -DLEAK_DETECT -I/opt/intel/mkl/include/fftw/

After compilation, the executable file openmx is generated. If you run the following calculation using this openmx,

  $ mpiexec -np 4 ./openmx Methane.dat | tee met.std

the following information will be printed at the end of the standard output.

  ID= 3 LEAK_DETECT result (0 / 990909)-----------------------
  ID= 1 LEAK_DETECT result (0 / 3061468)-----------------------
  ID= 2 LEAK_DETECT result (0 / 990909)-----------------------
  ID= 0 LEAK_DETECT result (0 / 3121674)-----------------------

The numbers in parentheses indicate the number of detected memory leaks and the number of memory allocations. In this case, the number of detected memory leaks is zero for all MPI processes. Please run the executable with the number of OpenMP threads set to one, since this tool is not thread-safe,

Let us examine a case where a memory leak occurs. Comment out the following lines in Free_Arrays.c as shown below, and recompile.

  /*
  for (Mc_AN=0; Mc_AN<=Matomnum; Mc_AN++){
    free(CellListAtom[Mc_AN]);
  }
  free(CellListAtom);
  */

If you run openmx again in the same way as above, the following information will now be printed at the end of the standard output.

  ID= 3 LEAK_DETECT result (3 / 991427)-----------------------
  ID= 3 memory leak!, addr:0x3262650
   size:81384
   file,line:truncation.c:5327

  ID= 3 memory leak!, addr:0x3262600
   size:4
   file,line:truncation.c:5324

  ID= 3 memory leak!, addr:0x32625b0
   size:16
   file,line:truncation.c:5323
    ...
    ...

This indicates that three memory leaks were detected for MPI process ID 3, and that lines 5323, 5324, and 5327 of truncation.c are related to the memory leaks. At these lines, CellListAtom is allocated by malloc. Since the memory allocated to CellListAtom is not actually freed, the relevant pointer can be identified.

To use this tool in other codes, include leakdetect.h in all source files that call malloc() and free(). In OpenMX, it is included in openmx_common.h.

  #include "leakdetect.h"

Then, call the leak_detect_init() function at the beginning of the main function, and call the leak_detect_check() function at the end of the main function. If these calls are enclosed by #ifdef LEAK_DETECT, the functionality can be enabled or disabled depending on whether the compilation option -DLEAK_DETECT is specified. An example is shown below.

  int main(){

    #ifdef LEAK_DETECT
     leak_detect_init();
    #endif

    ....

    Here, some calculations are performed.

    ....

    #ifdef LEAK_DETECT
     leak_detect_check();
    #endif
  }

Using the tool, one can easily idetify places in codes where memory leaks occur. Please run the executable with the number of OpenMP threads set to one, since this tool is not thread-safe, This feature also incurs additional overhead and slows down the execution time. Therefore, it should not be used for production runs.
