8.3 Generation of dat files from CIF files: cif2omx

A tool named cif2omx is provided to generate an OpenMX input dat file directly from a CIF (Crystallographic Information File) file. Compile it in the directory source as follows.

   $ gcc -std=c99 -O2 -Wall -Wextra -pedantic -DCIF2OPENMX_MAIN cif2omx.c -lm -o cif2omx

Please copy the generated executable cif2omx to an appropriate directory. Then convert a CIF file into a dat file as follows.

   $ ./cif2omx Si_mp149.cif -o Si.dat

Here, Si_mp149.cif denotes an arbitrary CIF file, and in the following explanation it may be replaced as appropriate. By specifying options, one can change the output dat filename, the coordinate mode, the basis quality, System.Name, the k-point mesh, and scf.energycutoff. As another way to generate an OpenMX dat file from a CIF file, one may also use the OpenMX Viewer described in Sec. 10. The OpenMX Viewer is convenient when one wants to create a dat file interactively while checking the structure on the screen. On the other hand, since cif2omx can be executed lightly on a terminal, it is suitable for batch conversion of many CIF files, use from shell scripts, and embedding into other programs. In addition, if the dat file generated by cif2omx is loaded into the OpenMX Viewer, one can visually check before running a calculation whether the atomic arrangement, unit cell, and treatment of periodicity are as intended. Thus, it is also useful to generate the input with cif2omx and then check the structure with the OpenMX Viewer. If cif2omx is executed without specifying a CIF file, the following help message is shown.

   $ ./cif2omx
   Usage: ./cif2omx input.cif [options]
          ./cif2omx --help

   Options (placed after input.cif):
     -o, --output FILE        Output OpenMX input (default: stdout)
     -c, --coord MODE         Coordinate mode: xyz | fractional (default: xyz)
     -b, --basis MODE         Basis quality: quick | standard | precise
                              (default: standard)
     -n, --name NAME          System.Name value (default: input filename stem)
     -k, --kspacing D         Set scf.Kgrid from reciprocal-space spacing D (1/Ang).
                              Uses reciprocal vectors including 2*pi and
                              Nk_i = floor(|b_i|/D), clipped to >= 1.
                              Default: D = 0.33 (matches OpenMX Viewer).
                              Example: -k 0.33
     -e, --ecut VALUE         Write VALUE to scf.energycutoff.
                              If omitted, the default value 220.0 is used.
                              Example: -e 100 writes scf.energycutoff 100.0
     -h, --help               Show this help

   If input.cif is omitted, this help is printed to standard output.

Note that the default value 0.33 for -k, --kspacing is chosen so as to be consistent with the OpenMX Viewer. Therefore, when generating a dat file from a CIF file, the way of determining scf.Kgrid can be made broadly consistent between the OpenMX Viewer and cif2omx. For the operations on the OpenMX Viewer side and the related visualization functions, see Sec. 10.

When used as an API

It is also possible to use cif2omx from another C program without creating an executable file. In cif2omx.c, main() is enclosed by #ifdef CIF2OPENMX_MAIN, so if it is compiled without -DCIF2OPENMX_MAIN, main() is not generated. In this case, the API consists of the following three functions: cif2omx_options_init(), cif_fp_to_openmx_opt(), and cif_result_free().

As a minimal setup, please place the following four files in the same directory.

   cif2omx.c
   cif2omx.h
   example_cif2omx.c
   Si_mp149.cif

Here, cif2omx.h is the header file that collects the functions and types, and example_cif2omx.c is a minimal usage example. Si_mp149.cif denotes an arbitrary CIF file, and in the following explanation it may be replaced as appropriate. First, compile cif2omx.c as an object file for a library.

   $ gcc -std=c99 -O2 -Wall -Wextra -pedantic -c cif2omx.c -o cif2omx.o

Next, link example_cif2omx.c with cif2omx.o to generate an executable file.

   $ gcc -std=c99 -O2 -Wall -Wextra -pedantic example_cif2omx.c cif2omx.o -lm -o example_cif2omx

Run the generated executable as follows.

   $ ./example_cif2omx

In example_cif2omx.c, Si_mp149.cif is read and Si.dat is generated. Therefore, if the above four files are placed in the same directory, one can check the behavior as is.

Below we summarize the minimum procedure that the user can follow directly.

   $ cp /path/to/cif2omx.c .
   $ cp /path/to/cif2omx.h .
   $ cp /path/to/example_cif2omx.c .
   $ cp /path/to/Si_mp149.cif .
   $ gcc -std=c99 -O2 -Wall -Wextra -pedantic -c cif2omx.c -o cif2omx.o
   $ gcc -std=c99 -O2 -Wall -Wextra -pedantic example_cif2omx.c cif2omx.o -lm -o example_cif2omx
   $ ./example_cif2omx

When used from the user’s own program, write #include "cif2omx.h", initialize the option structure CIF2OMX_Options with cif2omx_options_init(), and then call cif_fp_to_openmx_opt(). By using this function, all settings corresponding to the major options of the command-line version can be specified from the user-side program. However, the output destination corresponding to -o is given directly by fp_out, and the input CIF file is given directly by fp_cif, so they are not included in the option structure.

The correspondence between each member of CIF2OMX_Options and the command-line version is as follows.

system_name -n, --name
coord_mode -c, --coord
basis_mode -b, --basis
has_kspacing, kspacing -k, --kspacing
has_energycutoff, energycutoff -e, --ecut

has_kspacing and has_energycutoff are flags indicating whether kspacing and energycutoff, respectively, were explicitly specified by the user. When the value is 1, the corresponding value is used, and when it is 0, the default value is used.

In the distributed example_cif2omx.c, all major options are explicitly set. Its contents are as follows.

   #include <stdio.h>
   #include "cif2omx.h"

   int main(void)
   {
     FILE *fp_cif = fopen("Si_mp149.cif", "r");
     FILE *fp_out = fopen("Si.dat", "w");
     CIF2OMX_Options opt;

     if (fp_cif == NULL){
       fprintf(stderr, "Failed to open Si_mp149.cif.\n");
       return 1;
     }
     if (fp_out == NULL){
       fprintf(stderr, "Failed to open Si.dat.\n");
       fclose(fp_cif);
       return 1;
     }

     cif2omx_options_init(&opt);
     opt.system_name = "Si";

     // choose COORD_XYZ or COORD_FRAC
     opt.coord_mode = COORD_XYZ;

     // choose BASIS_QUICK, BASIS_STANDARD, or BASIS_PRECISE
     opt.basis_mode = BASIS_STANDARD;

     /* If opt.has_kspacing=1, you can specify opt.kspacing.
        If opt.has_kspacing=0, the default value of 0.33 (1/Ang.)
        is set to opt.kspacing.
     */
     opt.has_kspacing = 1;
     opt.kspacing = 0.20;

     /* If opt.has_energycutoff=1, you can specify opt.energycutoff.
        If opt.has_energycutoff=0, the default value of 220 Ryd.
        is set to opt.energycutoff.
     */
     opt.has_energycutoff = 1;
     opt.energycutoff = 300.0;

     if (!cif_fp_to_openmx_opt(fp_cif, fp_out, NULL, &opt)){
       fprintf(stderr, "cif2omx failed.\n");
       fclose(fp_cif);
       fclose(fp_out);
       return 1;
     }

     fclose(fp_cif);
     fclose(fp_out);
     return 0;
   }

Furthermore, if one also wants to receive the expanded structural information, pass a CIF_Result structure to res_out. In this case, the number of atoms is stored in res.n, the fractional coordinates of each atom in res.v[i].f, the Cartesian coordinates in res.v[i].r, and the unit-cell vectors in res.tv. After use, call cif_result_free(&res);.

In this way, when -DCIF2OPENMX_MAIN is attached, it can be used as a standalone executable, and when it is not attached, it can be used as a C library called through cif2omx.h.

When modifying cif2omx.c itself

The dat file generated by cif2omx.c is intended to automatically generate a minimum set of keywords. Therefore, depending on the user’s purpose, one may wish to modify cif2omx.c itself. In that case, it is convenient to first understand which function corresponds to which feature.

  • •

    write_basic_keywords() is the function that outputs System.CurrrentDirectory, System.Name, DATA.PATH, scf.XcType, scf.energycutoff, scf.Kgrid, scf.maxIter, MD.Type, Dos.fileout, Dos.Kgrid, and other basic keywords. Therefore, if one wants to modify the default SCF conditions, MD conditions, DOS conditions, or add general keywords, this function should be modified first.

  • •

    write_openmx() is the function that determines the overall structure of the output file. Within this function, it is determined in what order and in what format the blocks for the structure information comment, Definition.of.Atomic.Species, Atoms.SpeciesAndCoordinates, and Atoms.UnitVectors are output. Therefore, if one wants to change the output order, add comment lines, or insert a new block in the middle, this function should be modified.

  • •

    CIF2OMX_Options and cif2omx_options_init() define the kinds of options and their default values. If one wants to add a new option, first add a member to CIF2OMX_Options in cif2omx.h, and then set its default value in cif2omx_options_init(). After that, reflect the value in the actual output by modifying write_basic_keywords() or write_openmx().

  • •

    The option parsing for the command-line version is written together inside #ifdef CIF2OPENMX_MAIN. Therefore, if one wants to add a new option to the standalone version cif2omx, please modify the following three parts consistently: the help display, the getopt_long() settings, and the corresponding variable assignment. When it is used as a library, this part does not need to be modified.

  • •

    Reading of the CIF file, completion of symmetry operations, and expansion of atoms are carried out by cif_parse(), cif_try_fill_symops_from_db(), and cif_expand_to_result(). Therefore, if one wants to add support for additional CIF tags, change the treatment of symmetry operations, or modify the way the primitive cell is constructed, these functions should be modified.

  • •

    The default values of PAO, VPS, and the number of valence electrons for each atomic species are selected on the basis of the internal table and basis_lookup(). Therefore, if one wants to change the default basis for each element, or introduce another selection rule, that part should be modified. In particular, if one wants to change the contents of Definition.of.Atomic.Species, please also check the atomic-species output part in write_openmx().
